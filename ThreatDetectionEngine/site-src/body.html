Why a simple rule checker is not enough

Most student projects stop at “if failed logins > 5 then block”. That is easy to dodge and impossible to explain. AEGIS is built around two questions a security analyst actually asks: why was this flagged? and is this one step of something bigger?

How one event becomes a decision

Six steps, each in its own part of the code. Pick a step to see what happens and where to find it. A judge who asks “show me the code” gets a file name, not a promise.

    The scoring model

    The score is the sum of the points from every rule that fired. Because no single weak signal can reach 101 on its own, one noisy rule cannot block an innocent user. An attacker has to stay under every threshold at once to avoid it.

    One attack, nothing else

    +40 SQL_INJECTION

    A SQL injection from an ordinary address using a normal browser. Logged and shown, not blocked. Proportionate.

    Evidence stacks up

    +50 +15 +40 = 105

    The same injection, but from a known-bad address, using the sqlmap tool. Three rules agree, the score passes 100, and the address is blocked for 10 minutes.

    Password guessing

    10 + 7 × 5 = 45

    Twelve failed logins in two minutes. Points grow with each attempt but stop at 50, so guessing alone never blocks. That gap is exactly what the campaign view below closes.

    Catching what a per-event score misses

    The engine scores each event alone, so an attacker who spreads the steps out can stay below the block line every single time. The campaign view looks at everything one address has done and asks how far along the attack chain it has got.

    How campaign risk is calculated

    1. Collect the distinct rules this address has triggered.
    2. Weight each: its strongest points, times a repeat bonus (up to ×2), times a recency factor that halves every 10 minutes.
    3. Add 15 for every extra chain stage reached.
    4. Below 80 keep watching. From 80 escalate. From 150 a block is recommended.
    evidence(rule) = strongest points x repeat(n) x 0.5 ^ (age / 10 min) repeat(n) = min(2, 1 + 0.1 x (n - 1)) risk = sum of evidence + 15 x (stages reached - 1)
    Advisory by design. Campaign risk does not block anything yet, so the original engine behaves exactly as before. Wiring it into the response step is the first item on the roadmap.

    Why these numbers: the repeat bonus makes persistence count, because ten SQL injections are worse than one. The decay stops a quiet address from being punished for something it did an hour ago. The stage bonus rewards progress along the chain, which is what separates a campaign from noise.

    What we do not claim

    • Locations are estimates. Without a GeoIP database, real events are not plotted at all, and simulated events are drawn hollow.
    • Host rules are heuristics. Admin tools can trigger them, which is why they add points rather than block alone.
    • Weights are set by hand, not trained. This is a transparent rules engine, not a machine-learning model, and signatures can be evaded by a determined attacker.
    • Campaign risk is advisory. It flags and ranks. It does not block yet.
    • Three rules are outside the self-test: clock, baseline and feed dependent.

    Known limits, stated up front

    • Impossible-login tracking is per IP address, not per account.
    • The SQL rule matches the text --, so ordinary prose can trigger it.
    • Brute force alone tops out at 50 points by design and never blocks. The campaign view is what escalates it.
    • State lives in memory. A restart clears history unless alert persistence is on.

    Who it protects, and how to run it

    Small businesses, clinics, colleges and local government offices run the same servers attackers target, but cannot pay for a SIEM licence or a security team. AEGIS runs on a single Java installation. No cloud account, no API key, and logs never leave the machine.

    Run it

    # compile and start (JDK 21, nothing to download)
javac -d out $(find src -name "*.java")
java -cp out com.threatdetection.Main

# point it at real logs instead of the simulator
java -Daegis.web.log=/var/log/nginx/access.log \
     -Daegis.fw.log=/var/log/ufw.log \
     -cp out com.threatdetection.Main
